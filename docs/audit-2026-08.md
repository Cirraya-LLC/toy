# toy 首发前的一轮对抗审计：33 条发现，16 条确认，17 条被推翻

*2026 年 8 月 · toy v0.1.0 发布前*

toy 是一个装二进制的工具，它唯一的卖点是**装的时候一行脚本都不跑**。
一个把「不执行」当成产品的工具，必须先证明自己真的不执行 —— 所以在打第一个 tag
之前，我们对整个代码库跑了一轮对抗审计。

这篇写的是那一轮的过程和结果，包括**一条我们自己找出来的 critical**：
铁律 1 被完整绕过，而且绕得很干净。

---

## 1. 方法

审计分三段，故意让它们互相不通气。

### 第一段：八个攻击面并行找

不按包分工，按**攻击者想干什么**分工。八个面各自独立地读同一份代码：

| 面 | 问的问题 |
| --- | --- |
| 执行面 | 包里的代码有没有任何一条路能被执行？ |
| 哈希 | 「校验过了」在哪些情况下是假的？ |
| 路径 | 什么东西能写到它不该写的地方？ |
| 解压 | tar / zip 里能塞进什么？ |
| 终端注入 | 打给用户看的那一行能被改写吗？ |
| 签名 | 「✓ 已签名」到底证明了什么？ |
| 网络 | 传输层能被降级、被重定向、被撑爆吗？ |
| 健壮性 | 什么失败会让用户处于一个比不装更糟的状态？ |

按面分而不是按包分，是因为**最贵的漏洞都跨包**。这一轮那条 critical 就是：
它一半在 `internal/store`（建软链），一半在 `internal/host`（执行 git），
单看任何一个包都看不出问题 —— 两个包各自都是对的。

### 第二段：每条发现三视角对抗证伪

三十三条发现出来之后，**不是拿去修，是拿去推翻**。每条发现由三个独立视角去论证
它走不到：

- **可达性**：从一个真实的入口出发，这条路真的能走到吗？
- **前提**：它需要的前提条件成立吗？还是需要攻击者已经拥有更强的能力？
- **语义**：这是漏洞，还是用户显式要求的行为？

一条发现要活下来，得同时扛住这三问。**结果是 17 条被推翻，比确认的还多。**

这个比例是有意义的。一轮全部确认的审计，通常说明标准太松 ——
每条「看起来不太对」都被记成了发现。

### 第三段：确认的按包分组修

16 条确认的按包分组，一次改完一个包再改下一个。跨包的（那条 critical）单独处理。

## 2. 主菜：一个包能拿到执行权，而且铁律 1 的字面意思仍然成立

### 攻击

一个 `toy.toml` 里写：

```toml
[bin]
git = "payload"
```

装完之后，`~/.toy/bin/git` 就在 PATH 上。

而 `~/.toy/bin` 正是 `toy doctor` 教用户**放在 PATH 最前面**的那个目录 ——
必须放最前面，否则装的工具会被系统里的同名程序盖住。

**toy 自己靠 `git ls-remote` 发现版本。** 这是一个刻意的设计：不用 GitHub/GitLab
的 REST API，因为未认证 60 次/小时的限流会让用户第一天就撞墙，而且要写三套适配器。
`git ls-remote` 一条命令，所有 git 托管方行为一致。

于是：下一条 `toy install github:…`、`toy update`、`toy publish`、`toy doctor`，
执行的都是这个包里的文件。

**安装那一刻确实一行都没跑。** 铁律 1 的字面意思成立。执行只是**推迟了一条命令**。

### 为什么遮蔽检查挡不住

铁律 5 是「绝不遮蔽 PATH 上已有的命令，除非 `--force`」。它存在的理由就是
`bin = "sudo"` 这类攻击。看起来 `bin = "git"` 该被同一道检查挡住。

挡不住 —— 因为那道检查的判据是 `exec.LookPath("git")` **找得到东西**。

在一台**还没装 git** 的机器上，`LookPath` 找不到，就不算遮蔽，检查放行。

而「还没装 git 的机器」不是一个牵强的前提：

- macOS 没装 Xcode Command Line Tools —— 全新的 Mac 就是这样，`git` 是个会弹
  安装对话框的 stub。
- slim 容器镜像、CI 的基础镜像 —— 装 git 是要显式加一行的。
- **而 toy 的裸地址安装路径（`toy install https://…/toy.toml`）压根不需要 git。**

最后这条让整个前提自洽了：攻击者不需要受害者装过 git，他只需要受害者用裸地址装
一次东西 —— 而那正是 toy 最不需要任何前置条件的一条安装路径。

用户在这台机器上装的第一个 toy 包，可以是这个包。

### 修在两半，缺一半都不成立

**第一半，`internal/store` 的 `reservedLinkNames`**：拒绝把任何包链接成 `git`。

```go
// reservedLinkNames 是 toy 自己会按【名字】从 PATH 上 exec 的程序。
var reservedLinkNames = map[string]bool{"git": true}
```

这是**全项目唯一一条 `--force` 也不放行**的检查。

理由不是「更危险所以更严」，是**用户判断不出后果**。`bin = "sudo"` 那条提示说
「PATH 上已经有 sudo 了，确认要覆盖就加 `--force`」，用户读得懂：他知道 sudo 是
什么，知道覆盖它意味着什么。而「这个包想叫 git」对用户来说读起来像一个巧合 ——
没有任何东西告诉他，答应这件事等于把 toy 自己的下一次执行交出去。

一个包也没有任何正当理由要占住 toy 自己的工具链名字。这里不存在需要被解锁的
合法用例，所以这道门不该有钥匙。

**第二半，`internal/host` 的 `lookupGit()`**：自己走一遍 PATH，解析出绝对路径、
**跳过 `$TOY_HOME/bin`**，也跳过 PATH 里的相对项（`.` 和那个到处都是的空项 ——
在一个别人写得进去的目录里跑 toy，不该等于把铁律 1 交出去）。

假 git 是 PATH 上唯一的 git 时，不是含糊地报「找不到 git」，而是：

> 拒绝执行 —— PATH 上唯一的 git 是 `~/.toy/bin/git`，它在 toy 自己的 bin 目录里，
> 也就是说它来自某个装上来的包。toy 靠 `git ls-remote` 发现版本，跑它就等于让那个
> 包拿到执行 —— **这很可能是一次攻击**。

**为什么两半都要有：** 第一半只挡新装的包 —— 对一台已经中招的机器毫无作用。
第二半连一个已经躺在 `bin/` 里的 git 也不跑 —— 但它不阻止那个软链被创建，
而一个能被创建的假 git 会在别的场合（用户自己敲 `git`）生效。

### 留下的两处债

`internal/host` 不许 import `internal/store`（会成环），所以 bin 目录的推导逻辑在
两边各有一份，注释互相指认。**改一边忘了另一边，这条防御会静默失效，而失效的样子
和正常一模一样。**

以后 toy 只要新增一个「按名字 exec 的外部程序」，就必须同时加进 `reservedLinkNames`。
这一条现在只靠注释和这篇文章记着 —— 没有任何自动化会在有人加第二个 `exec.Command`
时提醒他。

复现在 `cmd/toy/ironlaw1_audit_test.go`、`internal/store/link_audit_test.go`、
`internal/host/exec_audit_test.go`。

## 3. 另外几条

### 索引改一行 `source`，就能换掉一个已装包的内容

索引条目只是个**指向仓库的指针** —— 这是刻意的设计，因为它意味着从索引里删掉一条
只是「不再被搜到」，`github:owner/repo` 那条路照样能装，没有人能真的封杀一个包。

代价是：`toy update` 会按索引条目重新解析。把 `source` 从 `alice/tool` 改成
`evil/tool`，用户 PATH 上那个命令的内容就换成了另一个仓库的东西 ——
**而且一道闸都没有**：

- 信任降级检查只拦 `signed → 非 signed`。两边都没签名时它什么都不做。
- TOFU 记录的 id 是 `<host>:<owner>/<repo>@<tag>`。source 一换就是一条**全新记录**,
  于是判定成「首次安装」，不警告、直接钉住。

同源的第二条：**作者公钥的 TOFU 也钉在这个从 source 推出来的 id 上** ——
改 source 等于换身份，那把钉住的钥匙对新 id 不生效。

修法是把「来源变了」变成一件必须被声明的事：默认停下来，`--force` 能放行，
但**放行时必须打印换到了哪个仓库**。

### `search --json` 把「索引里有一把 key」直接报成 `signed: true`

一次签名都没验。

这条特别值得记，因为它是**同一个 bug 的第二次出现**。第一次是在集成阶段发现的：
`index.Entry` 当时连 `sig` 字段都没有，解析路径只要看见 `key` 就打「✓ 已签名」——
而索引是谁都能 fork、谁都能提 PR 的 JSON，抄一把公钥零成本。那次修的是人看的路径。

`--json` 是另一条路径，它被漏掉了。**一个安全判定有两个出口，修一个不算修。**

### `toy list` 的信任列能被一个包名顶出屏幕

这一条不需要任何控制字符。

`toy list` 用 tabwriter 排表，列宽 = 该列最宽那格 + 2。而 `name` 一路从 `toy.toml`
过来，校验只拒控制字符和路径分隔符 —— **没有长度上限，也不管里面有多少连续空格**。

于是一个包可以把 `name` 写成一整行伪造的表格内容：

```
cowsay    v3.2.1  ✓ 已签名 9f3c1a20  Derrity/cowsay
```

后面补空格补到超过终端宽度。结果在任何窄于这个 name 的终端上：

- 这个包显示成上面那行 —— 一个签名过的 cowsay。
- 它真正的「⚠ 未签名」被推到换行之后（`toy list | less -S`、tmux 里直接截掉）。
- **顺带把同一张表里 jq 那种正经包的信任列也一起顶出去。**

铁律 8 说信任等级必须如实打印给用户看。这条攻击没有让它撒谎 —— 它让它**看不见**，
而看不见比撒谎更难被发现。

修法有三层：每格按 rune 截断；表格先排进内存再逐行过转义层；
**信任列放第一列** —— 放第一列就不存在被左边那格顶出去这回事。

同一个面上还有一条更隐蔽的：转义函数号称覆盖 C1 控制字符（0x80–0x9f），
但**裸字节 `0x9b` 会原样穿过去** —— 快路径用 `strings.IndexFunc` 扫，它把非法
UTF-8 解成 U+FFFD（不是控制字符），于是整个字符串被判定成干净的直接返回。
`0x9b` 就是 8 位形式的 CSI，在按 8 位 C1 解释的终端上，`CSI 1A` + `CSI 2K`
= 光标上移一行 + 擦掉整行，正好够把上一行的信任等级重写掉。

而同一个码位写成合法 UTF-8（`0xC2 0x9B`）时会被正确转义 —— **同一个字节，结果
取决于字符串里别的地方有没有控制字符。一个看运气的消毒函数不叫消毒函数。**

### `net/http` 自己那条

toy 会在错误信息里回显 URL。用户可能把凭据写在地址里（`https://u:p@host/…`），
所以拼错误的时候要抹掉密码。

这一条做了，但漏了一个出口：**`CheckRedirect` 返回错误时，`net/http` 会把原始的
`Location` 塞回 `url.Error.URL`** —— 那条路不经过我们的抹除函数。

后果：一个上游只要把你重定向到 `https://user:pass@…`，就能借标准库这条路把凭据
带进错误对象里。而错误对象会进日志、进 issue、进 `--json`。

修法是在 `fetch.open()` 里就地抹掉，而不是依赖输出层兜底 —— 输出层是兜底，
不是修复。

顺带，同一轮里网络面确认的还有两条：**https 被重定向到 http 时静默降级**
（判据要扫整条 via 链，只比上一跳会漏掉 `http→https→http` 的中间那跳），
以及**下载没有体积上限**（判据必须是实际写入的字节，不是 `Content-Length` ——
服务器自报的长度是不可信的，而 chunked 传输压根不报）。

### `--force` 一个开关放行了六件事

三个独立的视角各自撞到了同一个问题。

`--force` 原来同时放行：重装同一版、artifact 哈希变了、作者公钥换了、命令名遮蔽、
信任等级降级、来源变了。

**用户想重装一次，就顺手接受了后面五件 —— 而那正是 TOFU 存在的全部意义。**

拆成两个：

- `--reinstall`：只表示「我知道已经装了这一版，再装一次」。**日常操作，不碰任何
  安全检查。**
- `--force`：接受安全检查报出的变化，**并且逐条打印它放行了什么**。

第二句是重点。一次静默的放行等于没有这道检查。

## 4. 被推翻的 17 条

这一节才说明这个流程不是走过场。

推翻的理由分三类。

### 「说得通，但走不到」

**`[artifact]` 的值写成 `file:///etc/shadow`，于是 toy 去读本机任意文件，
把它当二进制装进 PATH，还顺手缓存进 `~/.toy/cache`（那正是 `toy serve` 对外提供
的目录）。**

这条在提出的时候是成立的。但同一轮里另一条修复 —— `toyfile` 拒绝把
`artifact`/`script` 的值写成带 scheme 的绝对 URL —— 把它顺手堵上了：
地址只能由 toy 按托管方模板自己拼。

**git 的 `ext::` 传输能执行任意命令**（`ext::sh -c 'touch /tmp/PWNED'` 当仓库地址）。
两条独立的理由让它走不到：git 自 2.12 起把 ext 传输默认关掉了；更要紧的是
clone 地址的前缀来自 host 表（内置的四条或用户自己写的配置），owner/repo 被限成
`[A-Za-z0-9._-]`（连冒号都不允许）—— **包作者能控制的是 `toy.toml`，而 `toy.toml`
里没有任何东西能碰到 clone 地址。**

**跨主机重定向把 `Authorization` 带到第二台机器。** `net/http` 的
`makeHeadersCopier` 在换主机时会丢掉敏感头，URL userinfo 派生的那个也在内。

**重定向跳到 `file://` 读本地文件。** Transport 上没注册 file 协议。

### 「已经防住了，只是没人写下来」

这一类被推翻之后**变得更有价值**，因为它们指出了「一次看起来可以省掉的优化」。

**缓存命中不重算哈希**（只看文件名 = 声明的 hash 在不在，于是文件系统上任何人都能
造一个「名字对、内容错」的文件）。复核：不成立，代码里那句重算已经在了。

但这个重算**看起来就像一次可以省掉的磁盘 IO** —— 而省掉它就是把 `~/.toy/cache`
变成一个谁都能写的信任根，而那个目录还是 `toy serve` 直接对外提供的镜像源。

**下载失败留下半截临时文件**：不成立，一个标志位兜住了每一条失败路径。
但只要有人新加一条 `return` 而忘了它，缓存目录里就会开始长出半截文件。

**没有 sha256 时也去试镜像**：不成立，有一个提前 return。
镜像「不需要被信任」的全部前提就是内容可以按哈希核对 —— 哈希不在的时候，这个前提
不成立，那条回退路径必须**整个消失**，而不是降级使用。

**sha256 的大小写 / 空白 / `0x` 前缀处理**：两个方向都对。
守的是「宽进严出」那条线：大小写和空白是作者手抄 `toy.toml` 时的常见噪声，必须容忍；
而长度和字符集不能容忍 —— 因为这个字符串会被当成缓存里的文件名和镜像 URL 的路径段用。

解压面上被推翻的还有一批：setuid/setgid 位没有被带出来、硬链接指不到系统文件、
zip 的反斜杠和目录项同名、PAX 扩展头里的路径穿越、同名成员出现两次、超长路径、
umask 之后 chmod 会不会反而放宽权限、清理逻辑会不会删到界外。
**这些全部翻成了回归测试**，见下一节。

### 「那不是漏洞，那是用户要的」

**`toy install foo@v1.0.0` 装了一个比已装的 v2.0.0 旧的版本。**

推翻：那是用户**显式要求**的。拦下来只会让「我就是要回退一版」没法做。

但这一条推翻之后长出了一条真的发现，就在旁边：**上游把最新那个 tag 删掉**
（账号被接管、release 被撤、自建 host 被换掉）走的是**同一条路**，而那时输出里
只有一句「已安装 t 1.0.0」，一个字都没提降级。

所以现在装是照装，但**必须说一句**。

这是这一轮里最有意思的一次推翻：证伪一条发现的过程，把真正的问题挤了出来。
如果当时把它当成漏洞直接修掉（拒绝降级），我们会得到一个更难用的工具，
**而那个真正的问题会原样留在那里。**

## 5. 收尾：被推翻的发现留下的测试没有删

每一条发现在证伪之前都写了一个复现测试 —— 断言「这个攻击应该能得逞」。

被推翻的 17 条，测试**没有删，而是翻转成了回归测试**：断言从「应该能得逞」改成
「必须被拒绝」。每个文件顶上写清楚三件事：

1. 原本怀疑什么
2. 为什么不成立
3. 现在守的是什么

举一个：

```go
// 回归（铁律 4）：缓存命中必须重新算哈希，不能只看文件在不在。
//
// 原本怀疑：缓存只按文件名（= 声明的 hash）判命中，于是文件系统上任何人都能
// 造一个"名字对、内容错"的文件让它被直接装上去。
// 复核结论：不成立 —— Get 里那句 SumFile 已经在重算了。这条不是修复，是【钉住】
// 那次重算：它看起来像一次可以省掉的磁盘 IO，而省掉它就是把 ~/.toy/cache
// 变成一个谁都能写的信任根（那个目录还是 toy serve 的镜像源）。
```

理由很简单：**一条被推翻的发现，推翻它的是当前这一版代码。**
下一次重构可能就把那个理由拿掉了 —— 而没有人会记得曾经有人怀疑过这里。

这些测试现在在 `*_audit_test.go` 里，和确认修复的那些放在一起。它们的价值不是
「证明我们审过了」，是**把一次人工推理固化成一条机器每次都会跑的断言**。

## 附：这一轮之后定下来的约束

几条以后不能破坏的，都是这轮长出来的：

- `reservedLinkNames` 里的名字，`--force` 也不放行；新增一个 `exec.Command`
  就要新增一行。
- `--force` 和 `--reinstall` 是两件事；不要再把新的放行塞进 `--force` 而不打印。
- `✓ 已签名` 后面**不许印仓库 owner**。签名消息是 `id + source + toy.toml 原文`，
  三样都是公开可读的，**里面没有一个字节把公钥和 owner 绑起来**。详见 `SECURITY.md`。
- 一切给人看的输出都过转义层；表格先排进内存再逐行输出。
- 凭据在错误构造的那一刻就抹掉，不依赖输出层。
- TOFU 按资产名钉，不按 `ref@version` 钉 —— 否则共享 `$HOME` 的 musl 机器和
  glibc 机器会互相报「内容被人换掉了」，一个假警报出现在最不该狼来了的地方。
